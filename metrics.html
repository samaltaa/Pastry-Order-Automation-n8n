Column mapping: AI cost before and after optimization

Measured with the mapping eval (python -m evals.run_mapping --compare): 4 real POS layouts with a known answer key, 2 runs per pipeline, November 6, 2026. Baseline: Claude Sonnet 5.5 reads up to 50 raw rows as JSON. Optimized: code profiles the table first, Claude Haiku 5.5 maps it, and Sonnet takes over only when Haiku's answer fails the checks; the fixed instructions are prompt-cached.

Long-term cost

All numbers as a table
  • Where the saving comes from: when Haiku handles a layout on its own, a mapping costs about $0.001 instead of about $0.03. Two of the four layouts were escalated to Sonnet in both runs; those cost about $0.01, still below the baseline, but take two calls.
  • Speed: the optimized pipeline is about 50% slower per mapping when it escalates. Mappings run once per new column layout or CSV preview, so this is a good trade here; it would not be for a chat reply.
  • Caching: 1,867 of the 2,855 input tokens per call are the fixed instructions, read from the prompt cache at 0.1× the price when calls come within 5 minutes. A single mapping a day gets no cache benefit.
  • Projections multiply the measured cost per mapping by the volume you set, assuming the same mix of layouts as the eval. Larger tables than the eval's (thousands of rows) save more, because the profile stays small while raw rows don't.
